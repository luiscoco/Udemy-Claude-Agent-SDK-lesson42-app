01

Enable tracked file backups

Use enableFileCheckpointing and replay-user-messages. The SDK tracks edits through Write, Edit and NotebookEdit; the lab performs real Edit and Write calls.

02

Capture checkpoint identities

Save the replayed user-message UUID together with its session ID. These identify a pre-turn file state, not an arbitrary result message or a Git commit.

03

Preview and rewind

Use rewindFiles(id, { dryRun: true }) to inspect the native preview, then rewindFiles(id) to restore. Modified files recover their old content; tracked newly created files are removed.

04

Keep safe restore points

Automatically rewind when a real Node test fails. Or capture multiple turns, inspect their pre-turn snapshots and choose a known checkpoint through the web menu.

05

Rewind from a later process

Save and reload the session/checkpoint pair, open an empty resumed query with checkpointing enabled, then restore. Local transcripts and backup files must still be available.

06

Understand what remains

Conversation history stays intact. A distinct file changed only by Bash remains untracked. Checkpoints are session-specific, not a complete filesystem or remote storage snapshot.
